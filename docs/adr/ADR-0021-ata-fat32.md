# ADR-0021: ATA PIO + FAT32 read-only on a second disk

Status: accepted (Phase 7c). Date: 2026-10-03.

## Context

RAMFS is volatile and baked in. Real storage starts with a disk
driver and a real on-disk format: ATA PIO (no DMA/IRQ complexity)
plus read-only FAT32 on a second attached disk, grafted into the VFS
at /disk so the shell reads it unchanged.

## Decision

`kernel/drivers/ata.c`: primary channel, LBA28, single-sector PIO
polling with bounded spins; `ata_init` masks IRQ14/15 (polling never
waits on them). `tools/mkfat.py` builds a byte-deterministic
superfloppy FAT32 image (BPB at LBA0, 1 sector/cluster, /HELLO.TXT +
/DOCS/NOTE.TXT); nova.py converts to VDI and attaches at IDE P0D1.
`kernel/fs/fat32.c`: parsed (not assumed) BPB, FAT chain walks with
step caps, 8.3 uppercase-on-match, dot paths, no LFN, one static
scratch sector + 1-sector cache (dir scans re-read per entry; every
PIO sector costs hundreds of VM exits). VFS graft: exact "disk"
first component routes open/readdir to FAT (whole-file materialize
into owned detached nodes); mkdir under /disk is EROFS.

## Evidence

Guest: `ATA-OK` (LBA0 55AA + NVSC tag = our disk), `FAT-OK`
(contract asserts on generated bytes); typed `ls /disk` ->
HELLO.TXT/DOCS, `cat /disk/hello.txt` -> `hello from fat32`;
`nova test` 10/10 with T10. Host (T10): same driver vs the real
image + 20000-path fuzz, `VERDICT: fat32 correct`.

## Hard lessons

- Slow polling crosses the first BIOS timer tick (~55ms) with no IDT
  loaded: the IRQ vectors through IVT-as-IDT garbage and triple-
  faults (Guru 1155, eip frozen in the ATA epilogue). Fix is
  architectural: irq_init/timer_init/syscall_init moved BEFORE any
  disk I/O, so ticks vector to real handlers. Diagnosed via the VBox
  poweroff register dump (IDTR=0, PIT @18Hz, eip in ata epilogue).
- Faults before irq_init are undebuggable in-guest (no TRAP path):
  read VBox.log + the poweroff CPU dump instead of adding prints.
- `bytearray` slices COPY in Python: mkfat must pack at absolute
  offsets (caught by reading back signatures, not by booting).
- dir_clus must distinguish ENOTDIR (through-a-file) from ENOENT;
  split_parent must propagate it (host test caught both).
- FAT32 total-sectors-32 is at BPB offset 32, not 28.
- Set-1 reminder: s=0x1F (not 0x1E), disk=d-i-s-k order matters.

## Consequences

- Read-only (writes are EROFS), no persistence of ramfs, no FAT
  write path or fsck. Second disk is test-only fixture data.
- Next: FAT32 write (allocator), EXT4-read, NOVA-FS design; then
  Phase 8 drivers (DMA/IRQ disk I/O replaces polling).
