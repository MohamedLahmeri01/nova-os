# ADR-0070: Engineering hygiene — lint, CI gate, fuzz corpus (Phase F)

Status: accepted (v0.3 Phase F). Date: 2026-10-06.

## Context

v0.3 Phase F covered three hygiene gaps at once (empty
dirs, format/lint, CI, corpus). Constraints were tight:
no new host tools allowed (clang-format/tidy/cppcheck all
absent, silent installs forbidden), CI must be verifiable
here (not aspirational YAML), corpus must replay
deterministically.

## Decision

- **Empty dirs: deleted 14, kept 2.** Removed
  `kernel/{core,ipc,security,scheduler}`,
  `drivers/{display,input,net,storage}`, `fs/`, `net/`,
  `libs/{libc,libnova}`, `scripts/`, `examples/`,
  `userspace/{coreutils,services,shell}` (all 0 files;
  grep-verified unreferenced; `kernel/sync/` already
  filled by Phase E). Kept `tests/integration/` +
  README (stated intent) and `ci/` (filled below).
  Build skeleton list (`REQUIRED_DIRS`) updated to the
  intended layout — it had asserted the deleted dirs,
  which the gate run caught immediately.
- **`nova lint` (new command):** gcc `-fsyntax-only
  -Wall -Wextra` over every kernel/boot/userspace TU
  (freestanding flags), `py_compile` over tools, ADR
  continuity (0001..N, title agreement), no empty dirs
  under versioned trees. ERRORS/gaps/empties fail;
  warnings counted + reported (no `-Werror`: see below).
- **Warnings triaged, three fixed:** virtio hex-print
  `?:` sign-change (rewrote as one int expression),
  irq vector compare (dropped a redundant cast),
  smp AP_TRAMP duplicates (deleted; header is the single
  source). Remaining: exactly 1 (jail_selftest's
  defensive zeroed frame — genuinely unused, kept
  deliberately). `-Werror` waits on nothing now except
  policy courage; deferred one phase to watch the count
  stay at ≤1 rather than legislate today.
- **`ci/gate.py` (verified gate):** lint + build + image,
  no VM — portable to any runner with mingw + Python
  (exit-nonzero on first failure). Full `nova test`
  stays dev/nightly (VBox-gated). No GitHub workflow
  shipped: YAML nobody has executed is decoration, not
  CI; the workflow lands when a runner exists to prove
  it (recorded, not promised).
- **Fuzz corpus** (`tests/corpus/`, 11 wire seeds +
  README): DHCP OFFER + 5 rogue shapes, DNS reply + 4
  rogue shapes, generated byte-for-byte by
  `tools/mkcorpus.py` from the in-test constructions.
  T14 replays each through the real parser against its
  recorded expectation (corpus dir via argv[1], absolute
  from nova.py — the argv-path precedent from image
  fixtures). Policy: new parser bugs land here first
  (file + table row, never inline-only); PRNG logic
  fuzz stays inline fixed-seed.

## Evidence

`nova lint` clean (errors/gaps/empties none, 1 tolerated
warning); `ci/gate.py` PASS (verified this session);
`corpus: 11 wire seeds replayed` in T14; full suite to
be re-run at commit (Phase H gates on it).

## Hard lessons

- The skeleton check asserting deleted dirs is the
  hygiene loop working as designed: the gate caught the
  inconsistency seconds after the deletion, not months
  later. Checks that encode intent pay for themselves.
- `*.bin` inside a C comment is a `-Wcomment` tripwire:
  the corpus comment introduced the first new warning in
  months. The lint command earned its keep within the
  hour (fixed before commit).

## Consequences

- Style baseline: zero errors, one documented warning.
  `-Werror`, clang-format, and hosted CI are explicit
  next steps with owners (this ADR), not wishes.
- Fuzzing foundation: wire-codec corpus live; FS images
  already deterministic-as-code (`mk*.py`); shell-parser
  and packet-shape fuzz remain the gap (v0.4 candidates).
