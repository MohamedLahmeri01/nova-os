# ADR-0039: SDK headers + sample program + ABI reference (11a)

Status: accepted (Phase 11a). Date: 2026-10-05.

## Context

Ten phases built kernel and drivers, but userspace had no
contract: headers lived beside libc internals, programs were
hardcoded two in the build, the link script sat with init, and
the syscall table existed only in code. Phase 11a makes the
user/kernel boundary a documented kit.

## Decision

- `sdk/include/nova/` owns the public headers (nova/stdio/
  string.h, moved by rename from `userspace/libs/libc`; user
  code includes `nova/...`, `-I sdk/include`). `sdk/user.ld`
  owns the link (0x80000000, `.text.startup` entry).
- `build_userspace` grows a program manifest (name + sources;
  libc shared): init, hi, and `userspace/bin/uname.c`, the SDK
  sample (version + pid + uid, one `SDK-OK` line). Seeded as
  `/bin/uname`, boot-spawned after hi; `SDK-OK` gated in
  `run-vbox` (not `panic-test`: spawned threads never run in
  the fault image, same as HI-OK).
- `docs/ABI.md` is GENERATED by `python tools/nova.py abi`
  from the kernel table (numbers + dispatch names + errnos,
  with skew checks); T17 fails the suite when it goes stale.
- `sdk/README.md` documents the new-program checklist.

## Evidence

Guest `SDK-OK abi=1 pid=10 uid=0`; `nova test` 17/17.

## Hard lessons

- Gate placement must respect scheduling reality: markers from
  spawned threads belong in boot gates only. The fault image
  caught this instantly (T6 red until SDK-OK was removed from
  panic markers).
- Moves use renames (history preserved); include rewrites are
  byte-exact (binary mode: no CRLF churn in diffs).

## Consequences

- Any new user program is now manifest + seed + spawn + marker
  (checklist in sdk/README); new syscalls require an `abi`
  regen (T17 enforces).
