# NOVA OS v0.8 — Demonstration (executed, screenshot record)

Environment: VBox 7.2.6 headless (GUI equivalent:
click to capture), VERSION 0.8.0 image.

## Sequence (every step ran for real)

1. `python tools/nova.py build` → kernel 162772B.
2. `python tools/nova.py image` → vdi attached.
3. Start VM → ~16–25 s → console banner
   (`NOVA OS console…`), `NOVA OS 0.8.0 init`,
   `> ` prompt with cursor (shot v8_demo1).
4. Type `put /disk/v8.txt hello-v08`
   (no output = success, prints nothing on ok).
5. Type `cat /disk/v8.txt` → `hello-v08`
   (shot v8_demo2: write path proven).
6. Poweroff VM (hard power cut from outside).
7. Cold boot (~25 s), type `cat /disk/v8.txt` →
   `hello-v08` (shot v8_demo3: reboot persistence
   proven — bytes survived genuine poweroff).
8. Type `rm /disk/v8.txt` → `ok` (cleanup;
   shot v8_persist7 from the exploratory run).
9. Same shape on `/nova` (put/cat/rm, shot
   v8_persist5): NOVA-FS volume persistent too.
10. `python tools/nova.py test` → 23/23.

## Failure diagnosis

- `cat` shows wrong bytes: compare with
  `build/serial.log` (screen == log by
  construction); check no second VM shares the
  VDI (never share VDIs between VMs).
- Missing file after reboot: was it `put` to
  `/disk` or `/nova` (persistent) vs `/` or
  `/test` (ramfs, volatile by design)?
- Boot hangs: wait 30 s, read the serial tail,
  report the last marker.

## Limits restated

64 KB/file cap; no mid-write power-loss claims;
selftest scratch files rewritten every boot;
VDIs are test fixtures — copy them off powered-
off VMs for anything you want to keep.
