# NOVA OS P3.4 — independent ELF64 build (increment A)

This checkpoint introduces an **independently compiled and linked** position-independent
`nova-kernel-x64.elf`. It does not yet modify P3.3's verified `BOOTX64.EFI`
or boot path. The current UEFI program still links `early.c` directly and
does **not** load the ELF file from the FAT32 ESP.

Run from Git Bash after setting LLVM on PATH:

```bash
python tools/kernel64.py
```

Expected: `NOVA-KERNEL-ELF64-BUILD-OK`.
The script checks ELF64, little-endian x86-64 ET_DYN, bounded program headers,
PT_LOAD file extents, no W+X load segment, an executable entry point,
and unsupported runtime relocations. This is **build-time validation**, not
proof of firmware/kernel execution. The separate entry diagnostic marker
embedded in the ELF is `NOVA-KERNEL-ELF64-ENTRY-OK`.

The following P3.4 increment must implement and test:
UEFI SimpleFileSystem file reads, robust ELF segment layout validation, page
allocation/copy/zeroing, map-key/ExitBootServices lifecycle, and an explicit
entry handoff. The FAT32 disk builder must also be updated to place the ELF on
the ESP. Keep the P3.3 disk and legacy x86-32 VM unchanged; do not boot
physical hardware or merge the feature branch before successful emulator tests.
