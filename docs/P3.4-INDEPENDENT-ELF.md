# NOVA OS P3.4 — independently loaded ELF64 kernel (experimental)

**Implementation committed; real VirtualBox execution is NOT YET VERIFIED.**

This branch replaces the P3.3 embedded-kernel handoff with a UEFI loader that
opens `\\EFI\\BOOT\\NOVAKERN.ELF` using UEFI SimpleFileSystem, reads up to 1 MiB,
validates a small relocation-free ELF64 ET_DYN, allocates loader-code pages,
copies PT_LOAD segments, zeros uninitialized memory and then obtains the firmware
memory map, calls ExitBootServices, switches to a dedicated stack, and calls
the independent ELF entrypoint.

The independent executable is `build/uefi/nova-kernel-x64.elf`; the firmware
executable remains `build/uefi/BOOTX64.EFI`. On the FAT32 disk,
the kernel uses the 8.3 name `EFI/BOOT/NOVAKERN.ELF`.

## Build using Git Bash on Windows

```bash
export PATH="/c/Program Files/LLVM/bin:$PATH"
python tools/uefi.py build
python tools/make_uefi_disk.py
```

The first command builds both the independent ELF and the loader, and copies
the short-named kernel into the QEMU virtual-FAT tree. The second places BOTH
files into the separate 128 MiB raw FAT32 image. It writes only
`build/uefi/nova-uefi-fat32.img`, never a physical drive.

Expected *build-only* output includes:

```text
NOVA-KERNEL-ELF64-BUILD-OK
UEFI-PE-OK
FAT32-UEFI-IMAGE-OK
```

For VirtualBox, convert the raw image into a NEW VDI named
`nova-uefi-p34.vdi`, and attach it only to the powered-off `NOVA-OS-UEFI`
VM. Preserve the working P3.3 VDI. The fresh serial log must include:

```text
NOVA-UEFI-X64-ENTRY-OK
NOVA-UEFI-ELF-FILE-OK
NOVA-UEFI-ELF-LOAD-OK
NOVA-KERNEL-ELF64-ENTRY-OK
```

If any marker is missing, **P3.4 is not verified**. The VM display may stay
at the firmware logo because this kernel prints only on COM1 and then halts.

## Limitations

This is a minimum executable-loading proof, not a secure or full OS boot.
The loader checks ELF program bounds and rejects relocation tags it knows
how to identify, but does not yet provide comprehensive malicious-image
hardening. It allocates a contiguous mapping for the small PIE with firmware
page tables; segment-level W^X/NX is not established. Runtime ownership of
memory map regions, interrupts, IDT, paging, physical storage, and production
drivers are not implemented. Do not run on real hardware or attach host disks.
Preserve the legacy x86-32 regression test gates and keep the PR draft.
